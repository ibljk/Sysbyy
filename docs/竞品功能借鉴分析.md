# 竞品功能借鉴分析：EquipShare 仪享

> 调研对象：https://equipshare.cn （实验仪器共享管理平台，Julinshen Technologies 商业 SaaS）
> 调研方式：登录机构管理员账号（珊瑚海 / 体验版）实测 + 前端源码结构分析（118 个接口、全部视图与字段）
> 调研日期：2026-10-07
> 目的：对标成熟商业产品，筛选可迁移到本系统（智云实验设备预约）的功能点

---

## 一、平台定位

一句话概括其产品主张：**让仪器预约、准入控制、费用核算真正连起来**。

与本校系统的最大差异在于三点：

| 维度 | EquipShare | 本系统现状 |
|------|-----------|-----------|
| 用户体系 | 多机构（租户）+ 平台订阅 | 单校单库 |
| 收费属性 | 机时计费 + 课题组经费账户 | 无 |
| 硬件联动 | Windows 锁屏客户端控制仪器电脑 | 无（纯软件） |

其中「收费」和「硬件」属于商业模式驱动的重投入方向，**毕设不必全量对齐**；但它在**资源配置、准入规则、运维台账**上的设计非常成熟，可直接借鉴。

---

## 二、功能全景（实测还原）

### 1. 角色模型（4 类）

| 角色 | 说明 |
|------|------|
| 机构管理员 ADMIN | 全局管理 |
| 仪器保管人 CUSTODIAN | 只管理自己名下的仪器（系统强制按保管人过滤数据） |
| 课题组长 GROUP_LEADER | 管理本组经费与成员 |
| 普通用户 USER | 预约使用者 |

> 借鉴点：**仪器保管人**是本系统目前缺失的中间层。本系统把仪器管理权限全给了管理员，实际场景中每台设备往往由某位老师/实验员负责，把「仪器管理」按保管人做数据隔离是很自然的增强。

### 2. 仪器资产（字段级）

新增仪器表单字段（实测）：

| 分组 | 字段 |
|------|------|
| 基础 | 仪器名称、仪器编号、分类（可即时新增）、型号、位置 |
| 管控 | **签到模式**（无需签到 / 移动端签到 / Windows 锁屏控制）、**保管人**、**开放预约/暂停预约**、**是否需要审批**、**是否需要资质** |
| 计费 | 基础价格（元/小时）、开放范围（按课题组）、组内优惠（按折扣 / 固定优惠价） |
| 资产 | 购置日期、购置金额、预计使用年限（仅管理员可见） |
| **预约时间规则** | 最小预约时长（15 分钟~8 小时）、最大预约时长、**开放天数**（今天起 N 天内可约）、**允许跨天预约**、**每日开放开始/结束**（0:00–24:00，支持"全天"）、**同时可预约人数**、**允许使用中延长**、**无冲突自动通过延长**、**周期预约**（开关 + 最长跨度）、**最大积压机时**（未完成预约时长上限）+ 积压机时计时范围（全时段 / 仅工作时间） |
| 描述 | 仪器描述、封面图（JPG/PNG ≤5MB）、文档资料（PDF/TXT/图片/Word/MD ≤20MB） |

> **这是本次调研最有价值的单点**。「预约时间规则」全部挂在**单台仪器**上而非全局配置：同一套系统里，示波器可以"最少 2 小时、不可跨天、8:00–22:00 开放"，而离心机可以"最少 30 分钟、可跨天、全天开放"。
> 本系统目前把"最长 30 天"放在 `sys_config` 全局配置，改为仪器维度后，既贴合真实实验室，也是论文里"配置化规则引擎"的现成素材。

### 3. 预约流程

**用户端（我要预约）**：左表单 + 右辅助双栏
- 预约模式：**单台预约 / 组合预约**
- ① 选择仪器（名称/编号/位置搜索）
- ② 预约时间：开始/结束日期时间 + **快捷时长按钮（1 小时 / 2 小时 / 半天 / 跨天）**
- 课题组 / 经费选择、**重复频率 + 重复到**（周期预约）、用途
- **右侧「当天占用时间段」**：选定仪器与日期后，实时列出当天已被预约或维护占用的时段
- 提交时**后端二次校验**（冲突 / 维护窗口 / 资质 / 预约规则），前端提示"列表只显示当前账号可预约的仪器、课题组和经费"

**状态机**（7 态，注意含"爽约"）：

```
待处理 PENDING → 已确认 CONFIRMED → 使用中 IN_PROGRESS → 已完成 COMPLETED
                     ↓ 拒绝 REJECTED   ↓ 取消 CANCELLED   ↓ 爽约 NO_SHOW
```

配套动作：审批通过/驳回、开始、结束、取消、**延长使用**、**费用调整**、**使用后评价（评分）**。

> 借鉴点：
> 1. **「开始/结束」与「审批」分离**——审批通过只是"有资格用"，真正开始使用是签到动作触发的。本系统可用「用户拍照归还」这条链路补齐前半段（扫码/点击开始使用）。
> 2. **爽约 NO_SHOW** 是独立状态。用户约了不来，与"取消"性质完全不同，是信用体系的数据源。
> 3. **右侧实时占用预览**：本系统已有"实时计算占用"，把它做成预约表单旁的辅助面板即可，交互成本低但体验提升明显。

### 4. 准入与信用（本系统完全空白，建议重点补）

**资质认证**
- 仪器可配置「是否需要资质」
- 用户提交资质申请 → 管理员授予 / 拒绝
- 资质字段：仪器、用户、**培训日期**、**有效期至**、备注
- 记录状态：有效 / 已撤销

**信用分**
- 爽约、超时自动扣分
- 信用体系设置（阈值可配）、信用分列表、冻结 / 解封、手动调整
- 预约页顶部会提示当前账号的可用状态

> 借鉴点：这两块是**投入产出比最高的**。数据表只要两张（`qualification`、`credit_record`），业务规则清晰，答辩时是"系统有治理能力"的有力证据。

### 5. 运维台账（本系统仅"维修中"单状态，可大幅扩展）

「维护报修」页含四个子模块：

| 子模块 | 关键设计 |
|--------|---------|
| **维护窗口** | 仪器 + 开始/结束时间 + **维护原因类型**（例行保养 / 设备校准 / 耗材更换 / 安全检查 / 故障排查 / 软件升级）+ 说明；状态：计划 → 执行中 → 已完成；**创建时若时间段已有预约，系统提示并由后端拦截** |
| 报修工单 | 报修 → 处理 → 关闭，工单状态：处理中 / 计划 / 停机维修 / 报废 / 已恢复 / 已关闭 |
| 保养计划 | 周期性保养排期 |
| 检定记录 | 计量检定台账，结论：**合格 / 不合格 / 限制使用**；支持导出 Excel |

> 借鉴点：
> - **维护窗口 = 一条特殊预约**。用同一套冲突检测逻辑复用到"停机维护"上（本系统已有 `countConflict`），改造量很小，但把"维修中"从手工改状态升级为"排期 + 自动拦截冲突"。
> - **维护原因分类**让台账具备统计价值（年度保养次数、故障率），比一个"维修中"标签信息量大得多。
> - 四个子模块都支持**导出 Excel**，答辩演示很讨喜。

### 6. 组织与经费

- **课题组**：每个用户有一个主课题组 + 多个协作组；组有组长、成员、经费
- **经费**：账户 + 编号，预约时绑定，费用自动归账
- **加入申请**：用户申请加入机构/课题组 → 管理员审批

> 借鉴点：本系统已有"实验室"维度。可把"课题组"简化为**经费/项目维度**或直接复用实验室分组，用于预约额度和统计归属。

### 7. 机构级配置

- **工作时间设置**：周一至周日逐日勾选 + 起止时间（默认周一至周五 08:00–18:00）；被"积压机时"统计范围引用
- 机构信息：名称、英文名、类型、省市、联系人
- 订阅管理（SaaS 商业化，本项目不需要）

> 借鉴点：**工作时间**作为全局参数，被"预约开放时段"和"超时判定"共同引用，比本系统散落的 `sys_config` 更有体系。

### 8. 运营与统计

- **驾驶舱**：实时大屏 + **公开分享链接**（对外展示，无需登录）
- 统计报表：机时利用率、机时趋势、预约占用率、仪器使用热度（近 7 天按预约数排序）、本月机时 TOP10、设备类型分布、状态分布
- 运营概览卡片：仪器总数 / 今日预约 / 待审批 / 近 7 日费用 / 存储空间
- **运营待办**：待审批预约、待加入成员等聚合提醒
- 公告：支持 通知 / 注意 / 紧急 三级徽标，可关闭
- 操作日志、文档中心

> 借鉴点：
> - **运营待办聚合卡**——把"需要管理员处理的事"集中成一个列表，比让用户自己翻菜单找待审批单要好得多，实现成本却极低。
> - **驾驶舱公开分享**：生成一个只读链接投屏，答辩演示效果极佳。

### 9. 硬件联动（差异化，暂不建议实现）

- Windows 锁屏客户端（`equipshare-client.zip`）：预约到点自动解锁仪器电脑、到期自动锁屏；管理员可远程一键断开
- 扫码签到：微信 H5 扫描设备二维码完成签到/签退

> 说明：这是其核心壁垒，但依赖桌面客户端 + 微信生态，超出毕设范围。
> **不过**：如果后续想加差异化亮点，本机已有 Tauri 桌面端的技术积累，做一个"扫码签到 + 到点锁定"的简化版客户端（不做系统级锁屏，只做应用层提醒）是可行路径。

## 三、借鉴优先级建议

### P0 · 高性价比（各 1–2 天，答辩加分明显）

| 功能 | 落地要点 |
|------|---------|
| **爽约状态 + 信用分** | 预约表加 `NO_SHOW` 状态；系统定时把"已通过但超时未签到"的单标记为爽约；`credit_record` 记流水，用户表加 `credit_score`；低于阈值禁止预约 |
| **预约评价** | 归还后允许打分（1–5 星 + 文字），仪器卡片展示平均分与评价数 |
| **公告栏** | `announcement` 表 + 三级徽标（通知/注意/紧急），用户端首页顶部横幅，支持关闭 |
| **操作日志** | `sys_log` 表已有，补一个管理端查询页（按人/时间/模块筛选） |

### P1 · 中等投入（各 3–5 天，论文内容更扎实）

| 功能 | 落地要点 |
|------|---------|
| **仪器级预约规则** | 设备表扩展：最小/最大时长、开放天数、允许跨天、每日开放起止、是否允许延长；校验逻辑从 `sys_config` 改为读设备配置 |
| **维护窗口** | `maintenance_window` 表（仪器、起止、原因类型、说明、状态）；复用已有冲突检测，创建时拦截与预约冲突的时段；原因类型做枚举 |
| **资质准入** | `qualification` 表（仪器、用户、培训日期、有效期至、状态）；设备加"是否需要资质"开关；预约时校验 |
| **报修工单** | `repair_ticket` 表（报修人、设备、故障描述、图片、状态流转、处理人、处理结果） |

### P2 · 差异化亮点（工作量较大，视时间取舍）

| 功能 | 落地要点 |
|------|---------|
| **机时计费 + 经费账户** | 设备加单价；预约结束后按实际机时生成费用记录；课题组/经费账户 + 月度账单 |
| **驾驶舱大屏 + 公开分享** | 现有看板升级为全屏可视化；增加一个只读分享路由 |
| **预约表单实时占用预览** | 预约弹窗旁展示"当天占用时间段"时间轴 |
| **扫码签到（简化版）** | 设备生成二维码，用户扫码进入签到页；配合 Tauri 客户端可做进一步联动 |

### 不建议借鉴

- 订阅续费 / 版本分级（SaaS 商业模式，与毕设无关）
- 多租户机构体系（单校系统引入会显著增加复杂度，收益低）
- Windows 系统级锁屏（依赖客户端与系统权限，风险高）

## 四、可直接复用的字段设计速查

**预约状态枚举（建议对齐）**
`PENDING 待处理 / APPROVED 已确认 / IN_PROGRESS 使用中 / COMPLETED 已完成 / CANCELLED 已取消 / REJECTED 已拒绝 / NO_SHOW 爽约`

**维护原因枚举**
`例行保养 / 设备校准 / 耗材更换 / 安全检查 / 故障排查 / 软件升级`

**检定结论枚举**
`合格 / 不合格 / 限制使用`

**工单状态枚举**
`处理中 / 计划 / 停机维修 / 报废 / 已恢复 / 已关闭`

**公告级别**
`通知 / 注意 / 紧急`
